# Research, provenance and production plan

Research dates: 2026-11-20. Scope: a browser-first driving/walking vertical slice, not a recreation of GTA V or its protected content. Asset credits are also available through the **Credits** link in the game.

## Implementation notes

The façade kits are collections of individual modules, not complete buildings. We assemble compatible wall/window/door pairs, interleave individual imported Midcity buildings, and use the Downtown kit for the skyline. We instance them by mesh and spatial chunk. The loading screen waits for environment, textures, player car, traffic and characters; failed resources can be retried or explicitly bypassed with fallbacks. Palm geometry is merged by material before instancing. This reduces draw calls and avoids rendering the whole district at once, but the scene remains demanding on software renderers. Character skeletons are cloned independently, with a basic procedural gait. There is no claim that these are motion-captured animations or photorealistic AAA characters.

Blender's [glTF exporter](https://docs.blender.org/manual/en/latest/addons/scene_gltf2.html) produces self-contained GLBs. `tools/build_map.py` is an optional Blender base-map generator; it could not run in this sandbox because system graphics libraries were unavailable. The playable map uses the Three.js base and imported GLBs; the Blender generator predates the imported façade layer and may overlap it.

## Route to higher fidelity

1. Replace the flat boulevard with authored city blocks, terrain, intersections, collision meshes, PBR detail, lighting and level streaming. Validate budgets on target GPUs.
2. Source additional individually licensed vehicles, characters, motion-captured animations, vegetation and audio. Verify skeleton compatibility, LODs, commercial/redistribution rights, and trademark usage.
3. Add proper vehicle physics, obstacle handling, traffic routing, pedestrian navigation and animation blending, then interiors, missions, progression, save state and accessibility.
4. Profile draw calls, texture memory and bandwidth; add LODs, compression and occlusion, followed by playtesting and QA. A convincing AAA open world requires a multidisciplinary production, not just asset imports.
